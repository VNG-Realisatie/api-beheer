# Transfering naar een andere GitHub repository

Het kan voorkomen dat je componenten in de ene GitHub repository wil overzetten naar een andere/nieuwe GitHub repository. Bijv. als je een onderwerp wil afsplitsen.
In dat geval is het goed om rekening te houden met een aantal issues die kunnen spelen. Deze worden hier gedocumenteerd.

## Het overzetten van issues

Let bij het overzetten van issues overgezet op het volgende:
* Alleen issues kunnen overgezet worden. Met PR's gaat dat niet.
* Hou er rekening mee dat de issues hernummerd worden. Als er dus ergens verwezen wordt naar een issue nr. zonder dat dit een link is of door GitHub vertaald wordt naar een link dan raak je bij het overzetten kwijt om welk issue het ging.
* Indien issues in de bron repository onderdeel uitmaken van een projectboard en je wil in de nieuwe repo gebruik blijven maken van dat projectboard dan moet je niet alleen het projectboard opnieuw aanmaken in de nieuwe repo maar er ook voor zorgen dat je weet in welke kolom van dat nieuwe projectboard elk issue geplaatst moet worden.
In het oude projectbord zal elk issue na overzetten nl. verdwijnen en ook de historische informatie in de issues die aangeeft naar welke kolommen een issue in het oude projectbord verplaatst is geweest wordt verwijderd. Reproduceren van het projectbord kan dus erg ingewikkeld worden als je niet vastlegt in welke kolom elk issue moet worden opgenomen of niet elk issue meteen na overzetten in de juiste kolom plaatst.
Een goede werkwijze is wellicht om eerst het nieuwe projectboard met alle kolommen aan te maken en daarna vanuit het oude projectboard kolom voor kolom de issues over te zetten en deze weer meteen in de juiste kolomvan het nieuwe projectboard te plaatsen.
